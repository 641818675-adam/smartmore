# PartFinder Mobile UI/UX 专业点评（红点奖标准）

> 审查日期：2026-08-30 ｜ 对象：PartFinder Mobile v10.2.0（`PartFinderMobileV2/web/`，约 3465 行 UI 代码）
> 审查方式：通读全部 7 个 UI 文件、MuMu 真机截图 10+ 张（首页/详情/选型/客户/窄屏/弹层链路）、WCAG 2.1 对比度逐项实算（`scripts/contrast-check.mjs` + 合成背景复算）、设计规范文档与代码逐条比对。
> 标准：项目目标是「红点奖级软件」，故按红点评审口径审查——细节即道德，任何可判定的瑕疵都算数。

---

## 开头公道话（先说真话，再动刀）

这个底子比绝大多数「内部工具」好得多，有六处是真实的专业素养，不是装出来的：

1. **令牌系统是活的，不是装饰**。48 个 CSS 变量全部定义、零未定义引用、JS 渲染层零硬编码色值（grep 实测 `#[0-9a-f]{3,6}` 在 app.js 中 0 次命中）。深浅双主题由 `prefers-color-scheme` 真实驱动，`theme-color` meta 与令牌逐字节一致（`index.html:7-8` ↔ `app.css:10/76`）。
2. **数字排版意识在线**。料号/价格/计数全部等宽 + `tabular-nums`（`app.css:104-109`），跨行对齐防误读——工业工具最要命的一步，做对了。
3. **诚信文化**：无关键词浏览显示「共 1213 条 · 列出前 N 条」不虚报（`app.js:renderList`）；套包规则未覆盖时给琥珀色告警并明说「请人工补齐」（`app.js:kitWarningHTML`）；启动 spinner 绑定真实数据加载。**全应用没有一只假仪表**——这是很多参赛作品都做不到的。
4. **空状态分因且给出口**：筛选过窄 ≠ 无结果，文案不同、按钮不同（`app.js:searchEmptyCopy`）。
5. **无障碍骨架完整**：`focus-visible` 全局可见、卡片可键盘激活、aria-label 覆盖导航/图标按钮/复制按钮、`prefers-reduced-motion` 被尊重（`app.css:940+`）。
6. **动效克制且有据**：三档时长令牌（120/200/300ms）+ 两套缓动，无一处无限循环装饰动画（唯一 `infinite` 是数据加载 spinner，`app.css:628`）。

## 分维度批评（现象 + 证据 + 为什么严重）

### 1. 致命伤：对比度在「辅助信息层」集体失守（实算数据，非目测）

WCAG 2.1 实算（复合背景按 tint×透明度合成后取值）：

| 组合 | 实测 | 判定 | 用在哪 | 为什么严重 |
|------|------|------|--------|-----------|
| 亮 `--text-4 #b4b9c3` / 表面 | **1.97** | FAIL | 客户创建日期（11.5px，`app.css:832`）、全部占位符、空状态图标 | **真实内容（客户是什么时候建的）1.97:1，接近隐形**。红点评审第一眼就会划掉 |
| 暗 `--text-4 #4b515e` / 底色 | **2.44** | FAIL | 同上 | 同上，深色模式更差 |
| 亮 `--text-3 #8d93a0` / 表面 | **3.08** | 仅大字达标 | 区块标题（12px）、结果计数（12px）、提示文案（12.5px）——全是小字 | 全部低于 4.5:1，小字重灾区 |
| 暗 `--text-3 #6d7482` / 表面 | **3.74** | 仅大字达标 | 同上 | 同上 |
| 亮 `--st-active #0f8a4d` / 徽章合成底 | **4.62→实为 4.04~4.62** | 临界 | 「可售」徽章 11px | 临界踩线 |
| 亮 `--st-phasing #b25e00` / 合成底 | **3.94** | FAIL | 「准备下架」徽章、套包告警 13px | 告警文字本身不达标——警告看不见等于没有警告 |
| 亮 `--st-retired #7d838f` / 合成底 | **3.97** | FAIL | 「退市」徽章 11px | 同上 |
| 暗 `--st-retired #8d93a0` / 合成底 | **4.34** | FAIL | 同上 | 同上 |

「次要信息可以淡」是对的，但**淡到不可读就是把可访问性当装饰**。这 8 项全部可判定、全部可修，是本报告最优先的处刑对象。

### 2. 字号碎片化：14 种字号，规范文档写的是 7 级

`grep -oE 'font-size:\s*[0-9.]+px'` 实测 14 个不同值：12.5px×11、13.5×5、11.5×6、14.5×2、10.5×1……`docs/DESIGN_SYSTEM.md` §2.2 明明定义了 11/12/13/15/17/22 的字阶，代码里却散落着 12.5、13.5、14.5 这类半像素碎点。**文档说一套、代码长一套，规范就成了文学作品**。红点项目的字阶是铸出来就不可逾越的栅栏，不是建议。

### 3. 内联样式渗透：38 处 `style="` 长在 JS 渲染字符串里

`grep -c 'style="' web/js/app.js` = **38**。最典型的是同一行内联被复制了 6 次：`style="font-size:12.5px;color:var(--text-2);font-family:ui-monospace,monospace"`（`requiredHTML`/`optionalHTML`/`alternatesHTML` 各处）——这个重复既是字号碎片化的源头，也让「以后想调辅助行字号」变成 6 处手动同步。样式长在字符串里，令牌系统就被绕过了。

### 4. 死令牌与语义错位（颗粒级，但红点评审看得见）

- `--border-strong` 定义于 `app.css:24/58`，全仓**零引用**——设计系统里躺着一具尸体。
- 配件详情的速览行标签写死「机型料号」（`app.js:1016`），但 VS800P 配件安装包不是机型——**标签与对象语义不符**（真机截图 `audit_modal.png` 可见）。颗粒级文案，红点评审恰恰就扣这种地方。
- 导航标签 10.5px（`app.css:570`）低于可读性舒适线，且用 `--text-3`（3.08:1）双重打折。

### 5. 反馈件与空状态的颗粒度

- Toast 纯文本无语义图标，成功/失败只靠文字（`app.css:.toast`）。
- 空状态图标全站复用同一个放大镜（`app.js:emptyHTML` 固定 `ICONS.search`）——「暂无客户」「没有收藏」「竞品未导入」长同一张脸，浪费了三次建立产品人格的机会。
- `.mini-copy` 30px、`.mini-btn` 28px 视觉尺寸偏小（规范允许成组次级操作 ≥28px，但**热区**没有补偿），现场戴手套的销售会点名骂。
- 分段控件（竞品页 `.seg`，`app.css:703-708`）选中态只有颜色切换，无位移反馈——旁边底部导航都有指示点了，它没有。

### 6. 工程实现

- **不是 git 仓库**——一款以红点为目标的产品没有任何版本控制，改坏了就是真坏了。
- 无 package.json / 零依赖：这是离线约束下的**正确决策**（见下文「资源清单」的适用性说明），不是罪。
- 逐项检查通过：无 `window.prompt/confirm/alert`、无孤儿资源、无全局 `user-select:none`、无 `background-attachment:fixed`。

---

## 一句话总结

**你已经把 90% 的地基按红点标准打好了，却把最后 10% 的「次要信息层」交给了一组实测不到 3:1 的颜色和 14 个随手写的字号——红点奖评审不会看你做对了多少，只会看见客户创建日期在屏幕上隐形。**

## 资源清单（按本项目的特殊约束裁剪）

本项目为**完全离线、零依赖、手写构建链**（5 秒 aapt2→apksigner），引入任何 npm 组件库都违背其架构根基。因此不推荐「换个组件库换血」，而是把业界标杆当**参照物**离线对标：

| WCAG 2.1 SC 1.4.3 | 标准 | 本报告所有实算的判定依据 |

## 如果只做五件事

1. **把 8 组不达标的文字色提到 4.5:1（占位层提到 3:1）**——这是唯一一组「用户真的看不见」的缺陷，且全部是令牌级修改，一处改、全站生效。
2. **字阶收敛到 9 级并令牌化**（11/12/13/14/15/16/17/21/22），CSS 与 JS 内联一并替换——让 `docs/DESIGN_SYSTEM.md` 从文学作品变法律。
3. **38 处内联样式收编成类**（先消灭重复 6 次的 mono 辅助行）——令牌系统的最后一公里。
4. **颗粒文案与语义修正**：配件详情速览标签按对象切换「机型/配件料号」、空状态按语境换图标、Toast 加语义图标、复制按钮热区补偿。
5. **建 git 仓库 + 对比度回归测试脚本**——让这次修复的数字从此有守门员，防止三个月后悄然回退。
