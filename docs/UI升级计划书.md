# PartFinder Mobile UI/UX 升级计划书（红点目标）

> 版本：v1 ｜ 日期：2026-08-30 ｜ 依据：《UI点评报告-红点标准.md》（同目录）
> 方针一句话：先还债，再装修。诚信 > 系统 > 组件 > 核心体验 > 视觉 > 防复发。
> 约束：**功能与信息架构零改动**；完全离线零依赖架构不动摇；P2 按「内部组件正规化」裁剪（不引入外部组件库）。

## 〇、诊断结论摘要

| 维度 | 评级 | 一行结论 |
|------|------|----------|
| 设计系统完整性 | ★★★★☆ | 令牌真实存在且零死引用，唯 --border-strong 一具尸体 + 字阶文档漂移 |
| 诚信 | ★★★★★ | 无假仪表、计数诚实、告警真实——全项目最硬的一块 |
| 视觉语言 | ★★★☆☆ | 字号 14 种碎点、内联样式 38 处渗透 |
| 信息架构与交互 | ★★★★☆ | 动线清晰；颗粒文案（配件≠机型）与热区偏小 |
| 可访问性 | ★★☆☆☆ | 辅助信息层 8 组对比度实测不达标（1.97~4.34） |
| 性能与工程 | ★★★★☆ | 零依赖 5 秒构建；无 git、无对比度守门员 |

**核心问题**：辅助信息层可读性。**最大杠杆点**：全部缺陷集中在 2 个文件（app.css / app.js）的令牌与工具类层，一处修改全站生效。

## 一、升级目标（可判定）

1. 全部文字/背景实练组合 ≥ WCAG AA（正文 4.5:1，占位/装饰层 ≥3:1 并在规范中明示分档）。
2. 字号全仓只有 9 个值（11/12/13/14/15/16/17/21/22），且全部经由 `--fs-*` 令牌。
3. `app.js` 内联 `style="` 从 38 处降到 ≤8 处（一次性布局 shim 允许保留并注释）。
4. 全仓零死令牌（`grep --border-strong` = 0 命中）。
5. 每个空状态有语境化图形；Toast 成功态带语义图标；全部可点热区 ≥44px（含透明扩区）。
