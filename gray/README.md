# 灰度测试与自动迭代工作流

> 适用版本：≥ 10.1.0 ｜ 维护者：开发 agent ｜ 上次更新：2026-08-30

## 一、流程总览（可复用）

```
┌─────────────────────────────────────────────────────────────┐
│ 第 N 轮灰度迭代                                              │
│                                                             │
│  1. 打包 rc 版本        python build.py（改 VERSION_NAME）  │
│  2. 分发                真实用户：按 §三 清单执行            │
│                         本机沙箱：simulate.js 模拟面板       │
│  3. 回收反馈            用户端：收藏页「体验反馈」提交，      │
│                         复制 JSON 交给收集人 → inbox/        │
│  4. 聚合分析            node gray/collect.js <轮次>          │
│  5. 形成升级方案        findings 清单（每条带证据链）        │
│  6. 实施修复 + 测试     node tools/test_core.js / test_ui.js │
│  7. 记录                gray/rounds/ROUND-N.md               │
│  8. 下一轮或转正        rc(N+1) → 最终版                     │
└─────────────────────────────────────────────────────────────┘
```

## 二、反馈收集机制（双通道）

### 通道 A：应用内结构化反馈（主通道）
收藏页 → 体验反馈：1–5 星打分 + 问题类型多选（搜索/选型/竞品/客户/界面/性能/其他）+
自由描述。提交后自动复制结构化 JSON（含 app_version、data_version、屏幕宽度、深色
模式，**不含任何业务数据**），粘贴回给收集人即可。

字段定义见 `feedback.schema.json`。JSON 落到 `inbox/`，命名：
`r{轮次}-{用户编号}-{提交时间}.json`。

### 通道 B：自动化仪器（辅助通道，数据最可靠）
每轮附：`test_core.js` / `test_ui.js` 断言结果、`perf.js` 性能探针、MuMu 多分辨率
截图与 logcat 统计。findings 中每条问题都必须引用上述可复现证据。

## 三、真实用户分发清单（有分发渠道时按此执行）

1. 把 APK（`PartFinder-Mobile-v10.1.0*.apk`）+《一页使用说明》发给 50 位用户
   （推荐构成：销售 30 / 售前 10 / 渠道 5 / 管理 5；折叠屏用户 ≥ 10）。
2. 请用户安装前确认已卸载旧版或允许覆盖安装（同签名可直接覆盖）。
3. 明确请用户完成 6 个关键场景：搜型号 → 看详情 → 复制整包 → 选客户 → 竞品查对标 → 提交反馈。
4. 反馈回收：用户把「体验反馈」复制的 JSON 通过微信/邮件回传，存入 `inbox/`。
5. 回收期建议 5 个工作日；目标回收率 ≥ 70%（35 份）。

## 四、模拟面板（本沙箱专用，全程显式标注）

本机离线、无任何分发通道，无法触达真实用户。工作流不因此停摆：

- `personas.json` 定义 50 个**模拟**用户画像（角色/设备/熟练度/关注面）。
- `simulate.js` 读取 `findings/round-N.json`（每条 finding 必须携带
  `source_artifact` 可复现证据：测试断言 / 性能数据 / 代码走查位置），
  结合画像生成 inbox 反馈 JSON，**每条记录 `"simulated": true`**。
- `collect.js` 聚合时保留该标记，所有轮次报告醒目标注「模拟面板驱动」。
- 模拟反馈的改进依据 = 证据链本身（可独立复核），不是虚构的用户意见。

## 五、升级方案优先级规则

| 优先级 | 判定 | 响应 |
|--------|------|------|
| P0 | 崩溃 / 数据丢失 / 核心链路阻断 | 当轮必修 |
| P1 | 高频场景效率 / 明显误导 | 当轮修 |
| P2 | 一致性 / 可发现性 | 评估后排期 |
| P3 | 打磨项 | 记录，不阻塞转正 |

**不采纳规则**：与桌面版功能对等原则冲突的（如客户列表搜索过滤），记录不采纳理由，
桌面版对齐后同步。

## 六、产出物索引

| 文件 | 说明 |
|------|------|
| `feedback.schema.json` | 反馈 JSON 字段定义 |
| `personas.json` | 模拟面板 50 人画像 |
| `findings/round-N.json` | 每轮发现清单（带证据链） |
| `simulate.js` | 模拟面板反馈生成器 |
| `collect.js` | 反馈校验 + 聚合 → out/round-N-summary.md |
| `inbox/` | 反馈 JSON 落地目录 |
| `out/` | 每轮聚合报告 |
| `rounds/ROUND-N.md` | 迭代记录：变更点 / 反馈摘要 / 改进依据 / 验证结果 |
